# v0.12.20 Live Surface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render live Rock Band frames on the Android 16 display with bounded, fenced image ownership.

**Architecture:** Patch pinned Vortek swapchain acquire/present to use indexed leases and synchronization; Android native bridge presents buffers through SurfaceControl API 36 with release callbacks. Retain fallback heartbeat and final preview.

**Tech Stack:** C11, Android JNI/NDK, Java, pinned JICA98/vortek, Android 16, host gcc tests, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-06-v01220-live-surface-design.md`

## Global Constraints

- Android minSdk31, compile SDK35, runtime API36 for live feature, NDK26.3.
- No game content modifications, no user-data deletion, no root.
- Last verified v0.12.19 code and emulator runtime stay available; versionCode26 for update.
- Never hand Android an in-flight GPU write or reacquire a compositor-owned image.

## Review Focus

- No API36 function on lower Android: fallback heartbeat and truthful diagnostics.
- Same-frame multiple window callbacks and unexpected swapchain image counts: never alias buffers.
- Surface destroyed or probe stopped: callbacks never access freed session state.
- Unsignalled release fence: frame is not returned to the producer.
- Queue-submit failure: frame is not posted to Android.
